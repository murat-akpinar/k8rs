- *(fixtures)* Re-capture, and add the pending CSR for C3 ([85d087b](https://github.com/murat-akpinar/k8rs/commit/85d087beae1144357f71798f199446b493e1bd89)) — verify passed 13/13 on the kind cluster, then the capture ran: 23 fixtures from v1.36.1. - *(rules)* Put the current time on the snapshot the rules read ([aaecf7b](https://github.com/murat-akpinar/k8rs/commit/aaecf7babe1e82445e8a6de2c4bfcdb32308a4e6)) — `ClusterSnapshot` carries `now`, as `meta::v1::Time` — the same newtype every decoded API timestamp already wears, so the comparison rule 12 and C1 make is two values of one type. A rule reads the clock as a field or it is not pure, and a fixture that pins the moment cannot expire.

### 🐛 Bug Fixes

- *(ci)* Let cargo-deny accept our own GPL licence ([2717bd2](https://github.com/murat-akpinar/k8rs/commit/2717bd2b7cfd8cccd785111652ee12f407dfc9fe)) — cargo-deny checks the root crate too, so the permissive-only policy written for dependencies rejected k8rs itself. The exception is scoped to this crate; a copyleft dependency is still refused.
- *(fixtures)* Sanitize every shape the capture produces, not just one object ([842a767](https://github.com/murat-akpinar/k8rs/commit/842a767f95fac9bc1522a8000c74c9344fdd896b)) — Found by auditing Phase 2 before running the capture — nothing was failing.
- *(fixtures)* Strip addresses, and guard the pinned certificate dates ([90b8f66](https://github.com/murat-akpinar/k8rs/commit/90b8f6640411cf811044f392191229a646cda168)) — Three findings, all from checking claims against reality rather than reading them.
- *(fixtures)* Redact secrets that are not the whole string ([99a7a53](https://github.com/murat-akpinar/k8rs/commit/99a7a53bdebb9726bc9570966a0edfa7224cbb82)) — The IPv4 rule was anchored to the whole value, so two ordinary shapes walked past it: "10.244.0.0/24", an address wearing a suffix, and "dial tcp 172.18.0.1:53: no such host", an address quoted in the message kubelet writes when it cannot reach one. Both were sitting in the committed fixtures. The filter's own comment argued the gap away on the grounds that a foreign capture is refused anyway — but the refusal keys on node names, and this cluster's nodes are k8rs-* whatever address the apiserver was given, so a kind cluster on a real LAN passes it and takes that LAN address out inside a message.
- *(guards)* Read the signatures kube actually writes ([206d144](https://github.com/murat-akpinar/k8rs/commit/206d144d4b5b35b3cfc53b8b6d22b0b0c64170c4)) — write-guard derives its ban list by parsing every &self method of Api<K>, so under-extraction is silent: a method it cannot read is a method that never gets banned. Against real kube-client 1.1.0 the line-anchored regex found 28 of 45. The 17 it missed include every patch* method, delete_collection, exec and entry.
- *(screens)* Make the 80x24 claim true, and measurable ([b2c444c](https://github.com/murat-akpinar/k8rs/commit/b2c444c86e2fb79ab94b7ccf1056883fb48913a1)) — "Minimum terminal: 80x24" was a claim nobody had measured. Measuring it needs display columns, not bytes: a correct 70-column frame line is 76 bytes, so wc -c would have been wrong on all 31 mockups.
- *(guards)* Refuse the node names that were not in .nodeName ([44230d0](https://github.com/murat-akpinar/k8rs/commit/44230d00563e2545be726036c7cac4cc6c9b1e7e)) — The foreign-cluster refusal read two fields. A node name identifies infrastructure in four more, all ordinary: status.nominatedNodeName, spec.nodeSelector["kubernetes.io/hostname"], metadata.labels["kubernetes.io/hostname"] — which the committed nodes.json carries for all three nodes, so this is not a hypothetical field — and the values[] of a nodeAffinity matchExpressions entry. A production capture arriving through any of them was sanitized and written instead of refused. Each now has its own assertion, so a partial fix cannot pass.
- *(guards)* Assert the claims the guards were only asserting in prose ([61c5483](https://github.com/murat-akpinar/k8rs/commit/61c54839b609946cbbf1f2b97cc6bb2328e05b9e)) — certs-test.sh states that a real cluster's client certificate never enters this repository, and asserted nothing of the kind. A throwaway from make-certs.sh is self-signed; anything issued by a real CA is not, so subject == issuer is the difference worth catching. It also read only the three fixtures it knows by name, so a fourth certificate dropped into tests/fixtures/certs/ was tested by nothing at all.
- *(screens)* Show the log-tab keys the help screen promised ([ce1c11f](https://github.com/murat-akpinar/k8rs/commit/ce1c11f74af299937feb60110dbdbcedfb805f25)) — help.md opens with "the footer always shows the keys valid right now; ? shows all of them", and its own rules say only keys that exist in this build appear. Three did not: f follow and c container, both recorded in D12, and Shift-P previous, which was recorded nowhere at all — it lived in the detail.md footer and in no decision. A key that exists in a mockup and nowhere else is a key nobody agreed to.
- *(fixtures)* Refuse a certificate request that names a real requester ([e0d2e02](https://github.com/murat-akpinar/k8rs/commit/e0d2e02a577f7533e589f99404260b9027c9a0a4)) — sanitize.jq treats a CSR's .spec.username and .spec.groups the way it treats node names — refused, not rewritten — against the set the pinned kind cluster issues by itself, read off the live cluster rather than recalled. .spec.extra and .spec.uid take the payload treatment instead: the credential id is a fresh hash every capture, so there is nothing to allowlist.

### 🧪 Testing

- *(fixtures)* Prove the predicates that decide a fixture is trustworthy ([03a1deb](https://github.com/murat-akpinar/k8rs/commit/03a1deb1c12d23cee7d38418fe297d4c628ac929)) — cluster.sh verify holds one jq predicate per fixture, and each decides whether that fixture reached the state its rule is about. They had only ever run against a live cluster, where being wrong is invisible both ways: too loose passes a pod in the wrong state, too tight burns the 420s timeout and fails a correct one — and jq cannot tell a broken filter from an unmet condition either, since both exit non-zero.
- *(fixtures)* Add the broken pod that has an owner, and fix a predicate that named one instant of a loop ([27c8443](https://github.com/murat-akpinar/k8rs/commit/27c8443319f050e53b51f95d5daab1228adf55d9)) — broken-owned is a Deployment whose pod crashes, so one object carries both halves of the owner chain: pod -> ReplicaSet -> Deployment. Every other pod fixture is bare, leaving the grouping key tested only in its no-owner case.
